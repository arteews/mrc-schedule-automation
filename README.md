# Расписание Минского радиотехнического колледжа

Автоматизация читает PDF с расписанием Минского радиотехнического колледжа, выбирает указанную в настройках группу и отправляет её расписание в Telegram. В Google Календаре она создаёт одно событие на весь учебный день: от начала первого занятия до конца последнего. Проект рассчитан на одного владельца Telegram-чата и одного подключённого Google-аккаунта.

Это копия **исходного кода и шаблонов n8n без личных данных**. Работающие контейнеры, база расписаний, PDF, сессия Telegram, токены и учётные данные Google сюда не входят. Для восстановления потребуются ваши собственные настройки и повторное подключение аккаунтов.

## Как поступает расписание

1. Отдельный обработчик в Docker через Telegram-клиент Telethon получает PDF от `@MRC_ScheduleBot` из диалога владельца. Для этого нужен вход в Telegram-аккаунт владельца: обычный Telegram-бот сам по себе не получает сообщения другого бота.
2. Обработчик проверяет новые сообщения сразу при поступлении и дополнительно просматривает последние сообщения примерно раз в 30 секунд. Полученные документы и очередь задач хранятся локально в SQLite, чтобы переживать перезапуск.
3. PDF разбирается по линиям таблицы и распознаванию текста. Обработчик находит строку группы из `SCHEDULE_GROUP`, читает предмет, время, преподавателя и кабинет. Дата берётся из имени файла `ДД.ММ.ГГГГ.pdf`, поскольку дата внутри PDF может быть ошибочной.
4. Если в новом PDF изменилось только расписание другой группы, уведомление не отправляется. Для выбранной группы сравниваются занятия, их время, предметы, преподаватели и кабинеты. Любое изменение этих данных вызывает новое сообщение с перечнем изменений и полным актуальным расписанием.

## Сообщения в Telegram

- При появлении расписания **на любую будущую дату** бот сразу сообщает, к какой паре приходить, и перечисляет все занятия дня. PDF на понедельник, полученный в субботу, обрабатывается сразу. Для следующего дня используется «Завтра», для более поздних дат — день недели и дата; изменения на сегодня тоже отправляются. В тексте заголовок и пары выделены жирным, время — курсивом, преподаватель и кабинет — цитатой.
- Полная пара показывается как две 45-минутные половины с 10-минутным перерывом. Занятие на половину пары показывает только свою половину. Короткое занятие использует точное время из PDF. Практика показывается своим диапазоном начала и конца. Ячейки, общие для нескольких групп, и объединённые ячейки таблицы обрабатываются отдельно.
- За 15 минут до конца каждого занятия приходит напоминание о следующем занятии, его кабинете и преподавателе. После последнего занятия сообщение говорит о завершении учебного дня.
- За 3 минуты до начала и конца каждого реального перерыва между занятиями приходит сообщение «🔔 Звонок через 3 минуты!». Например, для перерыва 14:25–14:35 уведомления приходят в 14:22 и 14:32. Учитываются перерыв между половинами пары и промежуток между парами; внутри практики не придумывается неуказанный перерыв. В самом расписании время занятий и перерывов остаётся фактическим.
- Сообщения отправляются только в Telegram-чат из `CHAT_ID`. Очередь исключает повторную отправку одного и того же уведомления. Если PDF не удаётся прочитать, бот сообщает об ошибке.

Все времена рассчитываются в часовом поясе `Europe/Minsk` по указанным в `parser.py` границам семи пар.

## Google Календарь

Как только появляется расписание на текущую или любую будущую дату, второй сценарий n8n создаёт **одно событие на весь учебный день** в основном Google Календаре подключённого аккаунта. Начало события — начало первого занятия, конец — конец последнего. Описание содержит полное расписание обычным текстом с абсолютной датой, чтобы оно оставалось актуальным после смены дня. Сохранённые будущие расписания восстанавливают очередь календаря после перезапуска, даже если PDF больше не присылали.

У события постоянный идентификатор для сочетания группы и даты. Если меняется пара, время, преподаватель или кабинет, сценарий обновляет существующее событие без дубля. Если занятия отменены полностью, событие удаляется. Неудачная запись остаётся в очереди и повторяется до подтверждения Google.

Для доступа используется OAuth-разрешение на работу с событиями календаря. Этот репозиторий не содержит Client ID, Client Secret, токенов или экспортированных учётных данных n8n. В режиме Google OAuth **Testing** долгоживущий доступ может истечь через семь дней; статус приложения проверяйте в Google Cloud.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `schedule_worker/parser.py` | Разбор PDF-таблицы и нестандартных занятий |
| `schedule_worker/worker.py` | Получение PDF, сравнение расписаний, очередь уведомлений и задач календаря |
| `schedule_worker/login.py` | Однократный вход в Telegram-аккаунт для чтения источника |
| `schedule_worker/Dockerfile` | Контейнер обработчика с OCR-зависимостями |
| `schedule-workflow.json` | Шаблон n8n: отправка сообщений в Telegram и подтверждение доставки |
| `calendar-workflow.json` | Шаблон n8n: создание, обновление и удаление события Google Календаря |
| `schedule_worker/test_*.py` | Тесты сравнения расписания, напоминаний, звонков и календаря на вымышленных данных |

В шаблонах n8n **нет привязанных учётных данных**. После импорта их нужно подключить в узлах Telegram и Google Calendar, затем опубликовать сценарии. Оба шаблона используют внутреннее имя контейнера `n8n-schedule-worker` для обращения к обработчику. Контейнеры должны находиться в одной Docker-сети. Публичный доступ к панели n8n для работы этой системы не нужен; панель можно оставить доступной только через SSH-туннель.

## Настройка для своего экземпляра

1. Скопируйте `.env.example` в приватный файл настроек и укажите свою группу, Telegram API ID/Hash, номер для входа, токен бота и числовой ID чата. Не сохраняйте заполненный файл в Git.
2. Соберите контейнер из `schedule_worker/Dockerfile` и подключите постоянный том к `/data`. В нём будут SQLite, скачанные PDF и Telegram-сессия. Запустите `login.py` для однократной авторизации владельца в Telegram.
3. Импортируйте оба JSON-сценария в собственный n8n. Создайте там учётные данные Telegram и Google Calendar, привяжите их к соответствующим узлам. Для Google разрешите работу с событиями календаря и настройте OAuth redirect URI, который показывает n8n.
4. Укажите в приватных настройках адреса двух webhook из `.env.example`, соответствующие вашей Docker-сети. После подключения аккаунтов опубликуйте сценарии.

Быстрая проверка логики на вымышленных данных в окружении с зависимостями из `requirements.txt`:

```sh
python schedule_worker/test_bells.py
python schedule_worker/test_calendar.py
python schedule_worker/test_change_notifications.py
python schedule_worker/test_nonstandard_reminders.py
python schedule_worker/test_future_schedules.py
```

## Что никогда не загружать в Git

Заполненные `.env`-файлы, Telegram `.session`, базы SQLite и n8n, PDF расписаний, журналы, токены бота, Google OAuth Client Secret и refresh token, реальные ID чатов, номера телефонов и адрес сервера. `.gitignore` блокирует распространённые имена и типы таких файлов; перед каждым новым коммитом всё равно проверяйте список добавленных файлов.
